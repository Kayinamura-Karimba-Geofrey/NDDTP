# Deployment (Render + Neon)

`render.yaml` is a Render Blueprint that deploys four resources:

| Resource | Type | Notes |
|----------|------|-------|
| `nddtp-api-gateway` | Docker web service | Built from `NDDP-BACKEND/api-gateway/Dockerfile` |
| `nddtp-auth-service` | Docker web service | Built from `NDDP-BACKEND/services/auth-service/Dockerfile` |
| `nddtp-frontend` | Static site | `npm run build` in `NDDP-FRONTEND`, SPA rewrite to `index.html` |
| `nddtp-redis` | Redis | Sessions and cache for auth-service |

Postgres is hosted on **Neon**, not Render.

## Secrets — set in the Render dashboard, never in git

Variables marked `sync: false` in `render.yaml` must be set by hand under
*Service → Environment*:

| Service | Variable | Value |
|---------|----------|-------|
| auth-service | `DATABASE_URL` | Neon pooled connection string (`...?sslmode=require`) |
| api-gateway | `SERVICE_URL_AUTH` | Public URL of auth-service, e.g. `https://nddtp-auth-service.onrender.com` |
| api-gateway | `CORS_ORIGINS` | Frontend origin, e.g. `https://nddtp-frontend.onrender.com` |

`JWT_ACCESS_SECRET` and `JWT_REFRESH_SECRET` are generated by Render. auth-service refuses
to start in production without them, so a misnamed variable fails loudly instead of
falling back to a public default secret.

## Database

- TLS certificates are verified by default. Neon uses publicly trusted certificates, so leave
  `DB_SSL_REJECT_UNAUTHORIZED` unset. Set it to `false` only for a self-signed local database.
- TypeORM `synchronize` is always off. Apply schema changes with migrations:
  ```bash
  cd NDDP-BACKEND/services/auth-service
  DATABASE_URL='<neon url>' NODE_ENV=production npm run migration:run
  ```
  Or set `DB_RUN_MIGRATIONS=true` on the service to run pending migrations at boot.
- `npm run seed` creates demo accounts with a public password and refuses to run when
  `NODE_ENV=production`. Do not override this with `ALLOW_DEMO_SEED=true` against a real database.
- Connection retries (10 × 5s) are there because Neon and Render free instances cold-start.

## Free plan caveats

Render free web services spin down after ~15 minutes idle; the first request afterwards
takes 30–60s while the gateway and auth-service boot and reconnect to Neon. Expect the
frontend's first login after idle to be slow or to time out once. Upgrade the plan, or add an
external uptime ping to `/health`, if that matters.

## Rotating a leaked credential

1. Rotate it at the provider (Neon → *Roles → Reset password*).
2. Update the Render environment variable and redeploy.
3. Removing the value from git does not revoke it: it remains in history and in any clone.
